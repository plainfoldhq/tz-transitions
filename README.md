# Time zone transitions table + DST test vectors (IANA tzdata, 1970-2050)

[![tests](https://github.com/plainfoldhq/tz-transitions/actions/workflows/tests.yml/badge.svg)](https://github.com/plainfoldhq/tz-transitions/actions/workflows/tests.yml)

A database-ready table of every UTC offset change (DST start/end and permanent offset changes) for IANA time zones, and DST edge-case test vectors for testing date-time code: nonexistent local times in spring-forward gaps, ambiguous times in fall-back overlaps, 30-minute DST (Lord Howe), +12:45/+13:45 (Chatham), changes at midnight (Havana).

Generated by script from the public-domain [IANA tz database](https://www.iana.org/time-zones) (tzdata 2026f) and checked against `zdump`, Python `zoneinfo` and JavaScript `Intl`. Made by Plainfold with AI assistance. Not affiliated with IANA.

## Python package: `dst-test-vectors`
Test your own time zone code against the vectors. Standard library only, Python 3.10+. On PyPI: https://pypi.org/project/dst-test-vectors/

```
pip install dst-test-vectors
```

```python
import dst_test_vectors as dtv

dtv.is_nonexistent("2026-03-08T02:30:00", "America/New_York")  # True: spring-forward gap
dtv.is_ambiguous("2026-11-01T01:30:00", "America/New_York")    # True: fall-back overlap

# Your function: (zone, naive local datetime) -> aware UTC datetime
def my_to_utc(zone, local): ...

assert dtv.check(my_to_utc) == []                     # "compatible" policy: earlier instant in overlaps, shift gaps forward
dtv.check(my_to_utc, policy="raise")                  # gaps must raise
dtv.check(my_to_utc, policy="later", zone="Europe/London")

# pytest
# @pytest.mark.parametrize("zone,local,expected", dtv.params(kind="gap"))
```

`dtv.cases(zone=..., kind="gap"|"overlap"|"normal", tag="midnight"|"odd_offset"|"delta_30min", year=...)` returns the bundled cases (the 36-case 2026 sample below). `dtv.load(path)` / `cases(path=...)` read any file in the same format, such as the full set's `dst_test_vectors.json`. CLI: `dst-test-vectors --zone Pacific/Chatham`, and `dst-test-vectors --check` to check this machine's `zoneinfo` (the helpers use your local tz database or the `tzdata` package; vectors are built from tzdata 2026f, so an older database can disagree, e.g. Cuba's 2026 rules).

Columns of the transitions table: `zone, utc, unix, local_before, local_after, offset_before_s, offset_after_s, delta_s, dst_before_s, dst_after_s, is_dst_after, abbr_before, abbr_after, kind` (`gap`, `overlap`, `no_offset_change`). Offsets are seconds east of UTC. DST columns follow tzdata, which uses negative DST for Europe/Dublin and Africa/Casablanca, so use `dst_after_s > 0` for "summer time in effect".

Find the offset in effect at an instant: take the zone's latest row with `utc <= t` and use `offset_after_s`; before the first row, use the zone's offset at 1970.

- The tz database is not a historical reference before 1970.
